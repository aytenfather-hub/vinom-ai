# ٢. البنية التقنية

## المنظومة
```
fruit-box-app/
├── packages/
│   ├── fb_core/      نماذج البيانات، التسعير، المستودعات (Repository)، الإعدادات، التعريب
│   └── fb_ui/        الهوية (Theme/Tokens)، المكونات، لغة الحركة
├── apps/
│   ├── customer/     تطبيق العملاء: Android + iOS
│   ├── website/      موقع الويب: Flutter Web بتخطيط ويب مستقل + صفحات عامة مُولّدة مسبقاً لمحركات البحث
│   ├── admin/        لوحة الإدارة: Flutter Web
│   └── signage/      شاشات المحلات: Flutter Web، بالعرض الأفقي، وضع العرض الكامل
├── backend/supabase/ ترحيلات SQL، سياسات RLS، الدوال، الاختبارات، Edge Functions
├── data/             بيانات أولية مرصودة (غير معتمدة)
└── docs/
```
التطبيقات الأربعة تشترك في `fb_core` و`fb_ui`، لكن لكل منها تخطيطه وتنقّله. الموقع **ليس** تكبيراً لواجهة الهاتف: له ترويسة وتنقّل ويب، وشبكات متعددة الأعمدة، وتذييل، وروابط قابلة للمشاركة.

## اختيار الخلفية: Supabase (PostgreSQL)
| المتطلب | لماذا Supabase |
|---|---|
| بيانات علائقية: فرع × منتج × حجم × إضافة × سعر × توفر | PostgreSQL علائقي حقيقي بقيود ومفاتيح، والتقارير بـ SQL |
| صلاحيات لكل فرع ودور | Row Level Security داخل قاعدة البيانات نفسها، لا في التطبيق فقط |
| سجل تعديلات لا يمكن تجاوزه | Triggers في قاعدة البيانات تكتب `audit_log` |
| تتبع الطلب لحظياً وتحديث الشاشات | Realtime على جدول الطلبات والعروض |
| تسجيل الدخول | Supabase Auth (رقم الجوال OTP أو البريد) |
| صور المنتجات | Supabase Storage مع سياسات وصول |
| الدفع والمنطق الحساس | Edge Functions تحمل المفاتيح السرية |
| Flutter | الحزمة `supabase_flutter` رسمية وناضجة |

**بديل تم رفضه:** Firebase/Firestore. قاعدة بيانات مستندية تصعّب التسعير لكل فرع والتقارير والقيود، وقواعد الأمان فيها أقل تعبيراً للصلاحيات المركبة.

**قرار مطلوب منك:** Supabase لا يملك منطقة استضافة داخل الإمارات (الأقرب: مومباي / فرانكفورت). إن كان هناك اشتراط لإقامة البيانات داخل الدولة، يمكن تشغيل Supabase ذاتياً على مزوّد محلي بالمخطط نفسه دون تغيير في التطبيقات.

## الفصل الآمن
- التطبيقات لا تحمل إلا `SUPABASE_URL` و`SUPABASE_ANON_KEY`. هذا المفتاح عام بطبيعته، وكل الحماية تتم عبر RLS.
- `service_role` ومفاتيح بوابة الدفع وبريد الإرسال تبقى **فقط** في أسرار Edge Functions (`supabase secrets set`)، ولا تدخل المستودع ولا التطبيقات.
- **السعر لا يُحسب في التطبيق:** الدالة `place_order()` تعيد حساب السعر من قاعدة البيانات، وتتجاهل أي سعر يرسله العميل.
- الإعدادات تُمرَّر وقت البناء عبر `--dart-define`، وقيمها الافتراضية آمنة:

| المفتاح | القيمة الافتراضية | الحالة |
|---|---|---|
| `FB_APP_DOMAIN` | `fruitbox.com` | **هدف فقط**، غير مؤكد التملّك |
| `FB_SUPPORT_EMAIL` | `info@fruitbox.com` | **هدف فقط**، غير منشأ أو مفعّل |
| `FB_EMAIL_SENDING_ENABLED` | `false` | لا يُرسل أي بريد قبل تأكيدك |
| `FB_PAYMENTS_MODE` | `disabled` | لا دفع حقيقي |
| `FB_BACKEND` | `demo` | يعمل ببيانات محلية دون خادم |

- `futitbox.com` مدرج في قائمة منع داخل الإعدادات، ويفشل الاختبار إن ظهر في أي رابط.

## النشر
لا يتم نشر أي شيء على الدومين قبل تأكيدك. البناء المحلي والاختبارات تعمل بالكامل على `localhost`.

## الويب ومحركات البحث (Flutter Web)
Flutter Web يرسم الواجهة على Canvas، ومحتواه لا تقرؤه محركات البحث بشكل موثوق. الحل:
1. **روابط نظيفة:** `usePathUrlStrategy()` مع تحويل كل المسارات إلى `index.html` على الخادم، فتعمل روابط مثل `/menu`، `/menu/cat_01`، `/product/cat_01_item_01`، `/branches`، `/offers`، `/track/ORDER`، `/policies/privacy` عند فتحها مباشرة أو تحديث الصفحة.
2. **صفحات عامة مُولّدة مسبقاً:** سكربت بناء (`apps/website/tool/prerender.dart`) يولّد لكل صفحة عامة ملف `index.html` حقيقياً يحتوي: `<title>`، الوصف، روابط hreflang (ar/en)، بيانات منظمة JSON-LD (`Restaurant` / `Menu` / `MenuItem`)، والمحتوى النصي الكامل (أسماء المنتجات والأسعار المعتمدة) داخل HTML. بعدها يُحمَّل Flutter فوقه للتفاعل.
3. `sitemap.xml` و`robots.txt` يُولّدان من البيانات نفسها.
4. **الاختبار:** Playwright يجلب HTML الخام دون JavaScript ويتحقق من العنوان والمحتوى، ثم يفتح الروابط المباشرة في متصفح حقيقي ويتحقق من الشاشة الصحيحة.
